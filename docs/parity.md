## 已接入的厂商操作

| 操作 | 移远 | TD Tech MT5700 |
| --- | --- | --- |
| IMEI 读取 | `AT+CGSN` | `AT+CGSN` |
| 模式读取/设置 | `QCFG usbnet`，保留平台映射 | `^SETMODE`，使用 hisilicon 映射 |
| 网络偏好读取/设置 | LTE 的 nwscanmode 与其他平台的 mode_pref | `^SYSCFGEX`，保留上游组合映射 |
| 软件重启 | `AT+CFUN=1,1` | `AT+CFUN=1,1` |
| 5G LAN 读取/设置 | `QCFG 5glan` | 不提供移远专有操作 |
| SIM 读取/能力/切换 | `QUIMSLOT`，兼容 QUSIMSLOT；失败回读最多五次 | `SCICHG`，软件状态在 AT 发送前写入，拒绝时也保留 |
| IMEI 写入 | `EGMR` 后总是 `CGSN` 回读 | `at^phynum=IMEI,...`，无硬件回读 |
| 频段锁定 | QNWPREFCFG 或 LTE QCFG 位掩码；高位频段不截断 | 按上游禁用 |

表中“已接入”表示软件路径存在并有主机测试，不表示已完成实机验证或所有平台的 1:1 验收。

## 已发现的上游差异

- `mt5700m-cn` 在上游数据库归类为 `huawei/hisilicon`，USB VID:PID 为 `3466:3301`。本项目规范为 `tdtech`，只接纳 MT5700 型号，不因此扩大到其他 Huawei 或 TD Tech 设备。
- MT5700 网络偏好的两网络组合被上游映射为单个代码。这一行为先保留，不能凭猜测修正。
- 移远 hisilicon 的模式读取和设置存在不对称分支；当前命令构造保留上游行为。
- 移远 hisilicon 锁频读取走旧 LTE 查询，但设置走 QNWPREFCFG；保留这一不对称命令分支。
- 移远旧 LTE 页面中 B7、B40 的辅助函数拼写错误导致选项遗漏。新 API 保留 AT 位掩码行为，界面可选频段优先使用 TOML 覆盖及型号资料，并补齐旧默认列表；这属于显示修正。
- 移远 NR 查询在 unisoc 和 lte12 上仍发出四条命令，保留被界面隐藏类别的原始错误；不将隐藏类别 ERROR 当成可见频段查询失败。
- MT5700 软件卡槽使用私有临时目录，保留服务重启后可读、设备重启后默认 0 的语义；字段 `hardware_verified=false`，不会冒充硬件查询。
- 对格式错误、控制字符等 API 输入进行明确校验；不能把外部输入直接拼接成多条 AT 命令。

## 验证方法

- Rust 测试覆盖解析、配置、数据库、并发调度和内核伪终端。
- 原生 HTTP→串口→厂商解析链路使用内核 PTY 验证，不调用旧 Shell/C 服务。
- 使用固定上游 RM500U-CNV 串口录制验证四条锁频查询、NSA 错误后的继续执行、可见频段列表与 SIM 解析。
- 队列页面已用明确标注的双 PTY 模组验证登录、查询、筛选、历史、移动/桌面布局，无浏览器错误；这不属于真实硬件验证。
- 服务测试启动真实进程，验证鉴权、六种日志等级、网卡绑定、配置原子更新与退出。
- WSL 镜像网络的回环路由不同于普通 Linux，网卡测试在隔离网络命名空间运行；不修改宿主机的网络配置。
- 真实模组、OpenWrt SDK、LuCI ACL 与 ARM64 运行结果仍需分别记录。

旧 `rpc-methods.json` 只用于核对功能覆盖，不是新 HTTP API 的兼容约束。接口文档见 `api.md`。
