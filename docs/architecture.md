# 架构约定

## 组成

浏览器通过 HTTP 访问 qmodemd 内嵌的 art-design-pro 页面和业务 API。qmodemd 内部负责配置、鉴权、设备发现、厂商命令与响应解析、串口调度、短信、转发和流量统计。SQLite 是运行数据存储。

LuCI 插件作为 OpenWrt 的服务管理入口，通过受限的 rpcd 方法与 procd 管理服务，展示运行状态、设置监听地址与端口、控制开机自启，并跳转独立后台。独立后台不能依赖 LuCI 才能使用。

## 配置唯一来源

`/etc/qmodem-rust.toml` 保存监听参数及业务设置，不将同一组设置复制到 UCI。LuCI 保存基本设置时应调用 Rust 提供的受限配置接口：读取原配置、修改指定字段、校验、同目录原子替换，保留其余配置和用户注释。当前已实现 `set-service` CLI 和原子保存测试，不直接使用 Shell 字符串替换 TOML；rpcd/LuCI 路由器联调尚未完成。

开机自启状态由 OpenWrt 的 init 脚本软链接表示，不额外复制一份布尔值到 TOML。监听配置改变后明确重启服务，并更新后台入口地址。LuCI 页面在后端停止时仍应能够读取和修改基本设置。

## 系统边界

- 内核驱动不重写；使用系统已安装的 USB、PCIe、MHI、QMI、MBIM 和网络驱动。
- 优先使用现有网络管理能力处理地址、路由、DNS、接口上下线。
- 只有协议或平台确实需要时才引入拨号工具，不要求设备安装原 QModem 的整套脚本。
- Rust 不能只包装原 Shell 调用再声称已经完成迁移；旧脚本仅作为行为参考。
- 不用编程语言推断性能。对比进程数、空闲内存、CPU、API 延迟、串口命令数量和闪存写入。

## 串口与并发

同一物理 AT 端口由一个调度器管理，按端口串行、不同端口并发。短信发送的提示符与 PDU 操作必须成为不可拆分事务。AT 超时后处理迟到响应，避免其污染下一条命令；URC 单独分流。缓存按模组与查询分类，写操作使相关缓存失效，并合并重复的并发查询。

## 存储

SQLite 保存短信内容、收发状态、SIM 索引、统计采样等数据，采用版本化迁移。短信去重不能只靠 SIM 索引，因为索引会复用；长短信合并、重启恢复、分页和保留策略需要独立测试。统计应批量持久化，避免高频写闪存。

“一个二进制和一个配置文件”指业务程序部署形态；SQLite、日志、OpenWrt 的 init/ACL/menu 文件是允许的运行数据或系统集成文件。

## 安全与故障语义

业务 API 必须鉴权；LuCI 与独立后台需要明确登录边界。敏感字段不得进入状态接口、URL 或日志。系统命令使用固定程序和独立参数，不拼接 Shell。配置校验失败不得覆盖有效配置。

不支持的功能、设备未连接、模组拒绝命令和未完成的实现必须分别返回明确错误，不能用空对象、默认值或模拟成功掩盖。模拟设备只用于明确标记的开发和测试环境。
