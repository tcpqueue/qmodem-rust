# MT5700 首轮试用修复

2026-09-12，GL-MT3600BE / ImmortalWrt 25.12-SNAPSHOT。
命令依据：用户提供的《MT5700M-CN 5G 系列模组 AT 命令手册》，01 版，2024-05-17。
手册和实机原始响应保存在本地，不提交原文、身份标识或凭据。

## 设备发现

非 AT 端口的正常探测失败单独放入 probe_notes。至少一个端口识别成功时，
页面显示识别结果，其他候选端口记录折叠展示；全部失败时仍返回清晰错误。
实机确认 ttyUSB1 成功，另外三个串口无识别响应，不代表整个模组识别失败。
修复 Vue 响应式对象不能直接 structuredClone 导致的“添加到配置”异常。

## 联网

未指定数据网卡时，只允许自动选择同一物理模组下唯一的网卡；不猜测其他路由器端口。
查询现有 OpenWrt 接口，识别同一网卡已经联网的情况，返回现有状态，不建立重复 DHCP。
已有其他 OpenWrt 接口管理时，断开和重拨由 LuCI 管理，后台显示入口及明确原因。
网络设置保存前重新读取其他配置字段，避免覆盖别的页面新保存的短信和启动设置。

手册第 16.1 节（383–384 页）规定 NDISDUP 参数为 cid,connect。
修正 PDP 非 1 时的参数颠倒和断开时 cid=0：建立使用 cid,1，断开使用 cid,0。
实机的 eth2 已由 LuCI mt5700 接口取得地址；本次确认点击连接返回 connected，
未执行中断现有连接的拨号或断开测试。

## 状态

增加 COPS?、^ICCID?（第 11.3 节，239–240 页）、^HFREQINFO?（第 13.16 节，314–316 页）。
解析 LTE/NR 的 PCC/SCC、频段、中心频点、上下行频率和带宽；LTE 频率按 100 kHz 换算。
MONSC 的驻留频点与 HFREQINFO 的载波中心频点分别显示，不相互覆盖。
号码等可选查询失败不再把整个状态标为失败，失败明细继续保留在查询响应中。
进入模组页面自动读取状态，切换模组清除旧设置值，增加网络偏好读取按钮。

实机确认运营商正常、ICCID 非空、NR n1、上下行带宽 40000 kHz；CNUM 返回错误，
号码显示未提供。NR 不提供传统 RSSI 的场景仍显示未提供，以服务小区的 RSRP/RSRQ/SINR 为准。

## 浏览器

局域网 HTTP 不提供 crypto.randomUUID，曾导致短信页初始化失败。
改用 crypto.getRandomValues 生成 UUID v4，保持发送幂等键规则。
配置加载失败时，联网、维护和转发页面现在显示错误，不再只留下空白页。
短信端口留空规范化为 null，避免配置校验将空字符串当成设备路径。

## 验证

92 项 Rust 测试通过，2 项前端回归测试通过，严格 Clippy、类型检查和前端构建通过。
ARM64 静态二进制已更新至路由器，原 TOML、令牌和 SQLite 保留。
实机 API 验证识别错误列表为空、网卡计划为 eth2、连接复用已有 mt5700 接口、状态字段补齐。
前一个二进制保留为 /usr/sbin/qmodemd.previous，便于回退。

## 第二轮：拨号冲突、登录缓存和短信交互

后续实机配置已改为独立 USB NCM 数据口，没有第一轮的静态 mt5700 接口。
模组 SETAUTODIAL 查询为使能、USB 数传、IPv4v6，NDISSTATQRY 报告两类地址已连接。
旧流程再次发送 NDISDUP，30 秒无结束响应，串口进入隔离。

依据手册 16.18 节（411–412 页），MT5700 默认改用 SETAUTODIAL 路径。
network.tdtech_dial_mode 支持 usb（默认）、ethernet、internal、ndis（兼容旧路径）。
前三种场景分别映射 1、2、0，APN/认证由同一命令配置，不自动混入 CGDCONT/AUTHDATA。
认证限制为无认证、PAP、CHAP；APN 最长 99 字节，用户名和密码最长 31 字节。
全部认证字段留空时省略可选字段，以保留模组已有 APN；自定义拨号前命令仍由用户控制。
联网配置被模组拒绝时立即停止，避免继续拨号并误报成功。

参考 inotdream/mt5700webui-openwrt-server 的拨号页面命令调用，对照手册独立实现 Rust。
巴龙联网增加独立组件，区分 USB 控制端口和实际数据出口，展示模组自动拨号、USB 模式、
地址协议和 PDP 配置；移远保留原拨号方式。巴龙页面隐藏移远 NAT 等不适用设置。
“保存并连接”先保存页面参数再执行连接，连接地址放在页面上部。
OpenWrt 的独立 DHCPv6 子接口现在合并到连接状态，保留独立的 ipv6_up/ipv6_pending。

AT 隔离后继续检查迟到结束响应，在完整结束响应和静默间隔后恢复同步。
未收到结束响应仍保持隔离，不重放写命令。恢复期限边界保留不完整行，避免丢失分片 OK。
队列和错误信息增加最后命令的白名单名称，不含参数、身份信息、密码或短信内容。
短信输入提示本身不表示事务结束；等待提示超时时发送 ESC 取消输入，不重新发送正文。
补充识别不带空格的数字 +CMS ERROR:/+CME ERROR:，避免把模组拒绝误报为超时。

本次实机 B024 对单独的 CMGS 头没有返回标准交互提示，旧短信流程卡在第二条命令。
仅做空输入探测和 ESC 取消，未发送短信。依据手册 9.14 节及参考项目，MT5700 提交改为
同一串口事务连续写入 CMGS 头、CR、PDU 和结束字节；移远保留提示后写入流程。
本次没有验证实际短信送达，先前结果不明的发送记录不会自动重发。

WebUI 成功认证后将令牌保存在当前标签页的 sessionStorage，刷新自动恢复。
退出或 HTTP 401 清除缓存；浏览器禁止存储时仍可在当前页面登录。

验证：101 项 Rust 测试、5 项前端/LuCI 测试、严格 Clippy、类型检查和 ARM64 构建通过。
真实浏览器验证刷新保持登录、退出清除、401 清除、巴龙配置字段及双栈状态、无运行时异常。
实机自动连接事务约 0.1 秒完成，eth2 获得 IPv4 和 IPv6 地址，绑定 eth2 的外网 ping 2/2 成功。
硬件验证覆盖当前 MT5700 USB NCM；移远、巴龙网口/内部场景及实际短信发送尚需分别验证。
